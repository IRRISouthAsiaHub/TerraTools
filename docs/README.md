# TerraTools documentation

| File / folder | What it is |
|---|---|
| `manual/TerraTools_User_Manual.pdf` | The user manual (seventeen tool chapters, input formats, screenshots). |
| `sample_data/` | One small simulated example input set per tool, in exactly the layout the tool expects. Ship this folder with the manual. |
| `make_sample_data.py` | Regenerates `sample_data/` (deterministic). |
| `make_screenshots.py`, `shotlib.py` | Drive the real app (offscreen) with the sample data and capture the numbered screenshots into `manual/shots/`. |
| `manual/build_manual.py`, `content_a.py`, `content_b.py`, `mdkit.py`, `render_pdf.mjs` | Assemble the HTML and print it to PDF with Microsoft Edge. |

## Rebuilding the manual

```bash
python docs/make_sample_data.py            # only if the example files change
python docs/make_screenshots.py            # all tools; or name some:  ... qtl gwas
python docs/manual/build_manual.py         # HTML + PDF (needs Edge, Node, pypdf) + the in-app Help page
python docs/manual/build_manual.py --help-only   # only the in-app Help page (no PDF)
```

The in-app **Help → User Manual** page shows `frontend/public/help/` (generated by the build above); run `npm run build` in `frontend/` afterwards so it ships in `frontend/dist`.

* The screenshot script launches the real application window offscreen, so close any running TerraTools first.
* It needs the portable R runtime (`r_runtime_build`) for the R-based tools and TensorFlow for BreedSight / Heterosis; a full run takes about half an hour.
* Callout captions come from `manual/shots/manifest.json`, written by the screenshot script, so figures and legends always agree.
* `pip install pypdf` is only needed to fill the page numbers into the contents page.
